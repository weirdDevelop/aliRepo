# ADR-010: Automation: Flows becomes the single rule engine; others consolidated gradually

| Date | Status |
|---|---|
| 2026-11-04 | Proposed |

## Context
Six rule engines: AutoReply, BotMenu, Flows, Followups, IgCommentAutomation, Campaign steps (+ YarAPI server-side automations).

## Problem
One trigger→condition→action model with safety controls (§9).

## Options considered
A) Keep all. B) New engine from scratch. C) Promote `Flows` (graph engine, 6 triggers, 19 node types, step/loop limits, SSRF guard) to the core; add versioning, dry-run, kill switch, quotas, event triggers from the outbox; migrate other engines into Flows templates one by one.

## Decision
C. Order: Followups → AutoReply → IgCommentAutomation → BotMenu; Campaigns stay in Notifications.

## Consequences
Each migration keeps the old engine until parity tests pass.

## Security impact
Rules execute with the rule owner's permissions re-checked; HTTP node keeps SSRF guard (+ DNS pinning).

## Performance impact
Bounded steps per run (existing MAX_STEPS=300, MAX_LOOP=200).

## Migration impact
Data copy into flow graphs with dry-run comparison on recorded events.

## Rollback considerations
Re-enable old engine per tenant.
