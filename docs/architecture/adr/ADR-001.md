# ADR-001: Modular monolith in plain PHP, strangler migration

| Date | Status |
|---|---|
| 2026-11-04 | Proposed |

## Context
~93k lines of framework-less PHP running on shared cPanel hosting (one cron/minute, no daemons, no Composer). The master prompt asks for many new capabilities and forbids microservices without justification (§3.1).

## Problem
How to structure new work without a rewrite and without infrastructure the hosting target cannot run.

## Options considered
A) Rewrite on a framework (Laravel/Symfony) — needs Composer, CLI workers, months of parity work. B) Microservices — impossible on shared hosting, no measurable benefit. C) Modular monolith: keep the app, add a structured `src/` layer, migrate legacy modules context by context (strangler).

## Decision
C.

## Consequences
New features land faster and safely; legacy and new code coexist for several releases; discipline enforced by tests (boundary checks).

## Security impact
Single deployable keeps the attack surface known; existing hardening (2.1.5/2.1.6) carries over.

## Performance impact
No new runtime cost; async work is cron-driven (latency ≤ 1 min plus end-of-request flush).

## Migration impact
None for data; code moves module by module.

## Rollback considerations
Each increment is a patch zip; previous zip restores previous behaviour.
