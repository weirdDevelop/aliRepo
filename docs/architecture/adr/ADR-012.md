# ADR-012: Time and locale: UTC storage, locale presentation

| Date | Status |
|---|---|
| 2026-11-04 | Proposed |

## Context
CRM stores Jalali dates as `VARCHAR(20)`; timezone hard-coded to Asia/Tehran.

## Problem
Correct sorting/filtering/SLA math and non-Iranian tenants (§13.2).

## Options considered
A) Keep strings. B) `DATE`/`DATETIME` UTC + tenant locale settings (timezone, calendar, number format); Jalali at the presentation layer.

## Decision
B; existing columns via expand–contract (migration 0010).

## Consequences
Reports and SLA calculations become correct across year boundaries.

## Security impact
—

## Performance impact
Sargable date filters.

## Migration impact
Parse-failure report before switching readers.

## Rollback considerations
Old string columns kept until contract step.
