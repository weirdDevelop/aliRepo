# ADR-005: Versioned migrations with baseline adoption

| Date | Status |
|---|---|
| 2026-11-04 | Proposed |

## Context
Schema evolves by idempotent `ensure()` code executed on every panel request (`index.php` l.31) and by CRM model self-migrations; no history, no rollback.

## Problem
Safe, reviewable, repeatable schema changes across installs and tenants.

## Options considered
A) Keep ensure-on-request. B) Versioned migration files + runner + baseline. C) External tool (Phinx/Doctrine) — needs Composer.

## Decision
B (see `docs/database/migration-plan.md`).

## Consequences
Explicit history and verification; ensure-on-request removed from the hot path.

## Security impact
Destructive migrations gated by backup marker + admin confirmation.

## Performance impact
Removes per-request schema checks (unmeasured cost, DB-08).

## Migration impact
Baseline 0001 marks existing schema as applied.

## Rollback considerations
Runner absent ⇒ legacy ensure still works (kept as fallback for one release).
