# ADR-004: Tenancy: single-tenant installs + database-per-tenant for hosted SaaS

| Date | Status |
|---|---|
| 2026-11-04 | Proposed ⚑ |

## Context
No tenant column anywhere; ~3,000 query sites; the `site_id` retrofit (2.1.1) stayed incomplete.

## Problem
Commercial multi-tenant SaaS with provable isolation (§12.3, Scenario G).

## Options considered
A) Shared DB + tenant_id. B) Schema per tenant (= DB in MySQL). C) DB per tenant + control plane. D) Install per tenant only.

## Decision
D for Jakojast and self-hosted Commercial; C for hosted SaaS (see `tenancy-strategy.md`).

## Consequences
Same code for every edition; SaaS needs a VPS; per-tenant backup/export/delete are native.

## Security impact
Isolation by connection; tenant from Host only; control plane separated.

## Performance impact
Shared server resources; heavy tenants can be moved to another DB server.

## Migration impact
Per-tenant migration orchestration (ADR-005).

## Rollback considerations
SaaS mode is new; self-hosted unaffected.
