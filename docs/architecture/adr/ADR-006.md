# ADR-006: Permission keys + roles + scopes; pages map to keys

| Date | Status |
|---|---|
| 2026-11-04 | **Accepted** by owner 2026-11-04 |

## Context
Fixed role ENUM + page lists + org-role pages; record rules ad hoc. Task/approval features need finer, scoped permissions.

## Problem
RBAC with scopes and ABAC policies, without breaking current users (§10.2–10.5).

## Options considered
A) Extend page lists. B) Permission keys `context.resource.action` + roles + scoped grants + policy rules in services. C) External policy engine (OPA) — not runnable on shared hosting.

## Decision
B (see `permission-matrix.md`).

## Consequences
Role templates editable per tenant; migration generates roles equal to current grants (diff must be zero).

## Security impact
Default deny; SoD rules; viewer stays read-only by DB guard.

## Performance impact
Permission set cached per request (one query, as P-04 refresh already does).

## Migration impact
Generated roles from existing `permissions_json` and `eb_roles`.

## Rollback considerations
Old page checks remain valid during transition (keys `<page>.page.view`).
