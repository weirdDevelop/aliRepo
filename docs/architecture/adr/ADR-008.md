# ADR-008: Events via transactional outbox; generic DB job queue; cron-driven

| Date | Status |
|---|---|
| 2026-11-04 | Proposed |

## Context
No broker available; existing send queue proves DB-backed queues work on the target hosting (`modules/Queue.php` claim/lock pattern).

## Problem
Reliable cross-context events, automation triggers, outbound webhooks and timers.

## Options considered
A) Synchronous direct calls. B) Outbox + DB jobs processed at end of request and by cron. C) External queue (Redis/RabbitMQ) — not available.

## Decision
B. Listeners idempotent via `eb_outbox_consumed`; jobs with backoff+jitter, dead-letter, manual replay (audited).

## Consequences
Event delivery at-least-once; consumers must be idempotent (stable keys, as introduced in 2.1.5).

## Security impact
Payloads contain ids, not PII.

## Performance impact
Latency ≤ 1 minute worst case; end-of-request flush usually seconds.

## Migration impact
New tables only.

## Rollback considerations
Disable dispatcher ⇒ events accumulate, nothing lost.
