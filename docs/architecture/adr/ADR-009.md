# ADR-009: REST v2 API alongside panel RPC; YarAPI-compatible conventions

| Date | Status |
|---|---|
| 2026-11-04 | Proposed |

## Context
Panel RPC (`?api=action`, 430 actions) is session-only and untyped; integrators and a future public API need stable contracts.

## Problem
API contracts with versioning, idempotency, pagination and error codes (§0.2, §15 #12).

## Options considered
A) Keep RPC only. B) REST v2 for new contexts, RPC frozen for legacy. C) GraphQL — no library without Composer, heavy.

## Decision
B (see `docs/api/*`).

## Consequences
New SPA screens use v2; legacy migrates opportunistically.

## Security impact
Same gate (session/API key, CSRF, permissions); `Idempotency-Key` store.

## Performance impact
Cursor pagination; ETags for optimistic concurrency.

## Migration impact
None.

## Rollback considerations
v2 can be disabled without affecting RPC.
