# ADR-007: Work (tasks/projects) as a new context; CRM tasks migrated into it

| Date | Status |
|---|---|
| 2026-11-04 | Proposed |

## Context
CRM `tasks`/`projects` are minimal (JSON subtasks/comments, assignee names as text, fixed status) and the master prompt forbids a second task engine inside CRM (§5.12).

## Problem
Provide enterprise task management as the single task system.

## Options considered
A) Extend CRM tables. B) New Work context with normalized tables; copy CRM data; CRM links tasks via Work Api. C) Integrate an external tool.

## Decision
B. CRM UI keeps its task page during transition, backed by Work Api.

## Consequences
One task engine for CRM, marketing and departments; history and dependencies possible.

## Security impact
Task visibility via scopes (project/board/unit) and confidentiality level.

## Performance impact
Indexed relational model replaces JSON blobs.

## Migration impact
Copy migration with mapping table; ambiguous assignees flagged for owner.

## Rollback considerations
Source CRM tables untouched for one release.
