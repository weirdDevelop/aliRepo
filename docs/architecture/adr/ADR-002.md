# ADR-002: Code organisation: `src/<Context>` with facades, extensions folder

| Date | Status |
|---|---|
| 2026-11-04 | Proposed |

## Context
Today: flat `modules/*.php` classes calling each other's tables freely (e.g. CRM bridge joins by phone).

## Problem
Enforce bounded contexts in a codebase without a framework or Composer.

## Options considered
A) Keep flat modules with naming conventions. B) Namespaced `src/<Context>/` + hand-written PSR-4 loader + facade-only cross-context calls, checked by a static test. C) Separate repositories per context.

## Decision
B. `Eb\<Context>\Api` is the only cross-context entry point; events in `Eb\<Context>\Events`. `extensions/<name>/` for optional packages with a manifest.

## Consequences
Clear ownership; static test fails the build on boundary violations; legacy remains until migrated.

## Security impact
Facades are where permission checks live (`can()` before any read by id).

## Performance impact
Autoloader adds negligible cost; OPcache recommended.

## Migration impact
None.

## Rollback considerations
Remove the `src/` loader line; legacy code unaffected.
